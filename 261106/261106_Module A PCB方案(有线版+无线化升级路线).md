# Module A（眼镜本体）PCB 方案 —— 有线版 + 无线化升级路线

状态：方案阶段，尚未打样
依赖文档：`261016/261016_固定与供电计划.md`（物理固定与走线）、`261017/261017_会议纪要对照记录.md`（模块化拆分决策）、`261014/ESP32CAM+OV9281 双摄眼动仪 · PC 直控方案可行性分析.md`（GC0308 必须 USB 直连 PC 的硬约束）

## 0. 前提：为什么眼镜上不放 ESP32 / 不走 WiFi

261017 会议纪要已确定模块化拆分：
- **模块 A**：轻量化眼镜，不集成全脸识别硬件
- **模块 B**：空间环境摄像头，独立于眼镜，负责全脸识别，走云端同步

既然环境相机和 WiFi 的职责已经转给模块 B，眼镜（模块 A）上没有必要再放一颗 ESP32 跑 WiFi——这会违背老师"避免过度堆叠技术、保持原型简单"的方向。GC0308 本身是 USB UVC 模块，必须有线直连 PC（硬约束，无法绕开，见 261014 文档约束一）。

**结论**：现阶段最简方案是让眼镜彻底变成 PC 的纯 USB 外设，OLED 也走 USB-I2C，不走无线。这是本文档的"有线版"。

无线化不是现在要做的事，但作为"进阶设计"的完整性，本文档同时规划了未来的升级路径，方便到时候直接套用，而不是推倒重来。

## 1. 有线版方案（当前阶段，推荐先做这版）

### 1.1 架构

```
PC ──USB──> [GC0308 眼动摄像头]  （直连，不经过自制板子，硬约束）
PC ──USB──> [自制小板：USB-C → CH341T] ──I2C──> [OLED 0.96" 模组] ──凸透镜+半反半透──> 眼睛
```

### 1.2 元件清单

| 元件 | 作用 | 选型参考（立创商城有现货） |
|---|---|---|
| USB-C 插座 | 板子唯一接口，接回 PC，兼供电 | TYPE-C-31-M-12 |
| CH341T | USB 转 I2C 桥接芯片，让 PC 直接当 I2C Host 驱动 OLED，板上不需要任何 MCU | CH341T（SSOP-20，贴片，I2C 模式） |
| 去耦电容 | 芯片供电滤波 | 0.1µF ×2（0402） |
| I2C 上拉电阻 | 如果 OLED 模组自身未带上拉，需要板上补 | 4.7kΩ ×2（0402，装不装看 OLED 模组实测） |
| OLED 接口 | 4 线 I2C：VCC / GND / SDA / SCL，接到已验证可行的 OLED+凸透镜+半反半透光路 | 用 OLED 模组自带的排针/FPC 座对应规格 |
| 过线接口（可选） | 仅做物理走线整理，让 GC0308 的 USB 线和本板的 USB 线捆成一束，不经过任何芯片，纯机械过孔 | 2Pin/4Pin 直针或 FPC 卡座 |

### 1.3 优点

- 眼镜上零 MCU、零 WiFi、零电池——真正的"光学智能眼镜"而不是"戴了块开发板的眼镜"
- PC 端用 `pyusb` 或 CH341 官方 Python/DLL 库直接写 SSD1306 寄存器渲染遮罩，不需要在单片机上写固件，开发链路最短
- 元件数极少（一颗桥接芯片 + 几个无源件 + 两个连接器），板子尺寸可以做到很小，塞进镜腿没有问题

### 1.4 待验证

- [ ] CH341T 的 I2C 驱动模式在目标 OS（Windows，PC 直控方案默认环境）下的库支持与延迟实测
- [ ] OLED 模组是否自带 I2C 上拉电阻（决定板上要不要焊上拉电阻）
- [ ] 板子实际尺寸能否塞进镜腿内部空间，和 261016 的配重/走线计划是否冲突

## 2. 结构工程参考：PCB 即镜框（Arduglasses 案例，2026-11-06 老师提供）

老师发来 Hackster 项目 [Arduglasses](https://www.hackster.io/bateske/arduglasses-d7c00a) 作为参考。先明确这个案例**是什么、不是什么**，再说哪些部分可以借鉴。

**项目本质**：Arduglasses 的 OLED 是**不透视的**——镜片本身就是屏幕，佩戴者看到的只是屏幕内容（图中蓝色骷髅图案是显示给外部观看者看的表情特效），不能看穿过去看真实世界。这和我们已经验证可行的"OLED + 凸透镜 + 半反半透"方案方向相反：我们的光路核心目的是**保留真实世界视野，只在需要处选择性叠加/遮挡**，这是 ADHD 场景下的硬性需求。**结论：不采纳 Arduglasses 的"屏幕即镜片"光学思路，第 1 节的有线版光路设计不变。**

但它在工程实现上有三点值得借鉴，和光路选择无关：

### 2.1 PCB 即镜框（板子承担结构件角色）

Arduglasses 把前框和镜腿直接做成刚性 PCB 的外形（而不是做一块小板塞进镜腿空腔里，另配塑料/3D打印外壳）。电路板本身就是骨架，省掉额外的壳体件，整体更轻更薄。

**对 Module A 的启示**：第 1 节的有线版小板目前默认"塞进镜腿空腔"这个思路，可以考虑升级为"板子本身就是镜腿骨架的一部分"，但要先确认两件事再决定要不要采纳：
- 刚性 FR4 板在鼻梁/铰链处的强度和佩戴舒适度（FR4 偏脆，长期佩戴弯折处容易疲劳断裂，需要用柔性过渡板解决，见下）
- 这会把 PCB 打样从"一块小板"变成"异形结构件"，打样复杂度和成本都会上升，是否值得在当前阶段投入，还是等光路和检测链路验证通过后再做这层优化

### 2.2 前框—镜腿柔性过渡板（解决刚性板跨铰链的问题）

Arduglasses 在前框和镜腿之间用了类似 FPC 的柔性板过渡，而不是软排线单独走线。如果采纳"PCB 即镜框"思路，这是必须配套解决的问题——刚性板不能跨越铰链转动处，需要一段柔性板或软排线衔接。

### 2.3 电源管理电路参考（补全第 3.3 节无线版的电源设计）

Arduglasses 的原理图里电源部分拆成独立的 **Boost（升压）** 和 **Charger（充电管理）** 两颗芯片，而不是一颗芯片包办。这验证了第 3.3 节里"TP4056 + LDO/升压"的拆分思路是常见做法，选型时可以直接参考这个模块划分，不用自己再摸索架构。

**结论**：这三点作为"进阶设计"的结构优化方向记录下来，但不改变第 1 节当前要打样的有线版方案——先把光路和检测链路验证通过，再决定是否把 PCB 升级为结构件。

## 3. 无线化升级路线（未来阶段，现在不做）

### 3.1 触发条件

只有在以下两件事都验证通过之后，才评估是否切换到这条路线：
1. 标定链路（场景像素 → OLED 像素的仿射映射）跑通且可重复
2. 瞳孔检测链路（当前 EllSeg 在 GC0308 上静态 86.9%、固定安装连续视频 100%）稳定性在实际佩戴场景下复现

在此之前投入无线化开发，属于 261017 会议纪要里老师明确提醒要避免的"技术过度堆叠"。

### 3.2 架构

```
PC ──WiFi──> [自制小板：ESP32-S3-WROOM-1] ──I2C──> [OLED 0.96" 模组] ──凸透镜+半反半透──> 眼睛
                     │
                  锂电池 + 充放电保护
GC0308 ──USB──> PC （不变，硬约束仍然存在，无法无线化）
```

**注意**：无线化只能解决"OLED 由谁驱动、要不要再拖一根 USB 线"这个问题。GC0308 作为 USB UVC 模块的硬约束（见 261014 文档约束一）不会因为眼镜其它部分无线化而消失——除非未来重新引入一块能当 USB Host 的小主板（Pi/香橙派这类，当前已被用户否决，见 261010 路线图废弃说明）。也就是说，**即使完成本节的无线化升级，眼镜依然会有一根线连 PC**，只是从两根（GC0308 + OLED）变成一根（只剩 GC0308）。

### 3.3 元件变化（相对有线版）

| 元件 | 有线版 | 无线版 | 说明 |
|---|---|---|---|
| 主控 | CH341T（无 MCU） | ESP32-S3-WROOM-1（或体积更小的 ESP32-C3-MINI） | 需要跑 WiFi 协议栈 + I2C 驱动 OLED，C3 封装更小更适合塞镜腿，但 S3 有更多 GPIO 和更强算力余量 |
| 供电 | USB 5V 直供，无需电池 | 需要锂电池 + 充放电管理芯片 | 新增：TP4056（充电管理）+ 保护板（过充/过放/短路保护，很多成品锂电池已自带，优先选带保护板的电芯） |
| 稳压 | 不需要（USB 5V 够用） | 需要 3.3V LDO 或升降压芯片 | 锂电池电压范围 3.0~4.2V，ESP32 需要稳定 3.3V，建议用 AMS1117-3.3（简单）或 TPS63020（效率更高但贵一些） |
| 接口 | USB-C | USB-C（仅用于充电，不再传数据） | 数据走 WiFi，USB-C 降级为纯充电口 |
| 天线 | 无 | PCB 天线或外置 IPEX 天线座 | 注意不要用金属外壳包裹天线区域（261016 文档已提醒这点对 ESP32-CAM 同样适用） |

### 3.4 升级路径的兼容性设计（现在画板时就该考虑的事）

即使现在做有线版，如果想让未来升级不用重新设计整块板子，布局时可以预留：
- CH341T 和 ESP32-S3/C3 都走 I2C 输出到同一个 OLED 接口，**封装尽量选 pin 兼容或至少走线友好的位置**，方便以后换芯片
- 预留电池接口焊盘（JST-PH 2Pin，不贴片，留空焊盘），即使有线版不用，占位不费钱
- USB-C 走线预留给未来"仅充电"场景，不需要现在就加 TP4056，但可以把 VBUS 走线留出来，方便以后加

这是"预留余地"而非"现在就做"，有线版照常只贴 CH341T 相关元件，预留焊盘留空即可，不影响当前打样成本和复杂度。

### 3.5 待验证（无线版，仅在触发条件满足后才需要推进）

- [ ] ESP32-S3 和 ESP32-C3 的 I2C 驱动 OLED 实测延迟（相对 CH341T 方案的额外跳一次 WiFi 的延迟代价）
- [ ] 锂电池 + 充放电电路加入后的整体重量变化是否突破 261016 文档的配平预算
- [ ] 天线位置与 GC0308/OLED 的物理距离是否会相互干扰（电磁 / 结构）

## 4. 总结：现在做什么，以后做什么

| 阶段 | 做什么 | 不做什么 |
|---|---|---|
| 现在（打样第一版） | USB-C + CH341T + OLED 接口，纯有线，零 MCU | 不加电池、不加 WiFi、不加 ESP32 |
| 标定+检测链路验证通过后 | 评估是否切换到 ESP32-S3/C3 + 锂电池的无线版 | 在验证通过前不投入无线化开发（呼应 261016 文档"电源/无线化"待解决项的既定结论） |
| 无线版验证通过后（更远期） | 评估是否把 PCB 升级为"板即镜框"结构件（第 2 节 Arduglasses 参考） | 现阶段不改变第 1 节的小板+塑料结构思路，不盲目追求结构一体化 |

有线版 BOM 极简、成本低、排错成本低，优先打样验证"USB-I2C 桥接驱动 OLED + 凸透镜 + 半反半透"这条光路在真实佩戴场景下是否成立——这是当前阶段真正要验证的核心问题，不是无线与否。
